Improvements

Removing Factory class from Tol — Constructors made public

The constructors of all concrete Tol pin and capture types are now public, enabling direct instantiation. The now-redundant Factory abstract base class and its test-side wrapper have been removed.

Impact: Simpler, more idiomatic code. Consumers outside the Tol assembly — including unit tests and custom test blocks — can now instantiate these types directly without the Factory workaround.

SOC123 subset solution now generated dynamically

The manually maintained SOC123.sln has been replaced with generate-subset-solution.cmd, which dynamically creates the customer demo solution using dotnet sln commands. This eliminates drift between the subset solution and the main repository.

Unit Test Example project added to release package

src/ReferenceLibraries/UnitTests is now included in the release package. It provides ready-to-run, annotated unit test examples covering the most common MSTest patterns used with C#RA:

  • State assertion — Assert.AreEqual, IsTrue, IsFalse
  • Parametrized tests — DataTestMethod / DataRow
  • Setup return values — mocking IG-XL hardware responses with Moq
  • Verify method calls — confirming a method was called with specific arguments
  • Verify property sets — confirming a property was assigned the correct value
  • Times.Never — asserting that a path was not exercised
  • ThrowsException — verifying expected exceptions
  • Callback — overriding alert messages with custom handlers

Use this project as a starting point when writing unit tests for your own test methods.

PortBridge support added to release package

src/ReferenceLibraries/PortBridge is now included in the release package. It provides a utility library (PortBridgeUtils) and a demo project (Demo_PB) for working with PortBridge register map access in C# test programs.

Conditions: Requires PortBridge to be installed and licensed on the tester. The tester type is passed during initialization via TheHdw.Tester.Type.

How to enable:

  1. Call Initialize.PortBridgeInit() once in your setup flow to initialize the PortBridge framework and launch the status monitor.
  2. Call Initialize.PortBridgeSetup() to load your register map (SVD file) and associate it with a test configuration.
  3. Use PBLib methods for all register and field access.

Available examples in Demo_PB:

Test method What it demonstrates
InitialSetup Load register map, validate hierarchical path resolution
ReadAndLogRegister Read register and field values, test against limits
Check_SiteGenerics Per-site register read/write using Site<int>
VerifyRegisterReadWrite Read-Modify-Write-Verify pattern, field-level access

Versioning

Adopted SemVer 2.0 (MAJOR.MINOR.PATCH) versioning strategy

C#RA now uses Semantic Versioning 2.0. The version number format signals the impact of each release:

Bump Meaning Action
PATCH Bug fix only, no API changes Update immediately — no code changes needed
MINOR New features added, nothing removed Update at your next opportunity
MAJOR Breaking changes Plan a migration sprint; read MIGRATION.md before updating

A rolling two-MAJOR support window is maintained: N and N-1 are supported; N-2 and older are End-of-Life.

APIs are never removed without a two-stage advance notice using [Obsolete]: first a compiler warning (at least one sprint before removal), then a compiler error in the next MAJOR release candidate. Never ignore [Obsolete] warnings — they are migration deadlines.

New documentation artifacts:

  • VERSIONING.md — one-page quick reference with decision tree and golden rules (repository root)
  • MIGRATION.md — breaking-change migration guide (repository root)
  • docs/getting-started/versioning.md — step-by-step consumer onboarding guide

Impact: Consumers can assess update risk from the version number alone, without reading the full changelog. Assembly version numbers now reflect the SemVer scheme.
