Parameters

captureType CaptType

The capture mode. Must be Teradyne.Igxl.Interfaces.Public.CaptType.Fail or Teradyne.Igxl.Interfaces.Public.CaptType.STV — all other Teradyne.Igxl.Interfaces.Public.CaptType values are rejected.

digitalPins IDigitalPins

Pins used to retrieve data during ReadFails()/ReadStv(). Required for reading captured data.

captureLimit int

Maximum number of cycles to store in HRAM.

timeDomain string

Optional parameter. Digital time domain name to configure. Default value is an empty string.

Remarks

Passing an empty string for timeDomain explicitly targets the System time domain (the domain comprised of all pins defined in the test program) via TheHdw.Digital.TimeDomains(""). Always go through TimeDomains(...), even with an empty string, to guarantee reads/writes are scoped to a single, well-defined domain.

Value for captureLimit must be -1 (max depth), 0 (hardware default), or a positive value not exceeding the hardware's MaxDepth for the active PatGen mode.

HRAM is a single hardware resource per time domain — CaptureType, Size, and the trigger arm/disarm state configured here are not scoped to this HramCapture instance. Constructing a second HramCapture against the same timeDomain reconfigures the hardware out from under the first instance, and calling Reset() on either instance disarms the trigger for both. Do not construct multiple concurrent HramCapture instances on the same time domain; finish reading one capture (ReadFails()/ReadStv()) and call Reset() before constructing the next.

ReadFails()

Reads the cycle offsets of failing captures recorded in HRAM.

public PinSite<int[]> ReadFails()

Returns

PinSite<int[]>

Failing cycle offsets per pin/site. Pins/sites without failures are omitted, including when HRAM captured no cycles at all (e.g. no trigger occurred) or when the hardware returns no cycle data for the read.

Remarks

CapturedCycles is a scalar whose derivation across multiple sites with differing capture depths is undocumented, so the maximum captured-cycle count across active sites (via CapturedCyclesPerSite) is used instead; when that maximum is 0 or less, an empty result is returned without issuing a read. As a further guard, a null captureCycleData from the hardware also short-circuits to an empty result rather than throwing.

Reads are issued via TheHdw.Digital.Pins(...) rather than through TheHdw.Digital.TimeDomains(_timeDomain), because Teradyne.Igxl.Interfaces.Public.DriverDigitalDomain does not expose a pin-scoped read API. In test programs that use multiple time domains over the same pins, this can resolve against the System time domain instead of _timeDomain.

Only WhichDataCycle 0 is read from each captured cycle. This is the only result for 1X pins, but for 2X/4X pins a failure that only shows up on DUT cycle 1..N-1 of a captured cycle is never reported — a silent false negative. Handling the pin multiplier is a known limitation of this implementation.

-1 reads all cycles captured in HRAM; true restricts the result to failing pins only (passing pins are stripped by the hardware). With captureLimit -1 (max depth) this marshals the entire HRAM contents across all pins/sites in a single call — be mindful of the cost for large captures.

ReadStv()

Reads the raw digitized bit values captured in HRAM.

public PinSite<double[]> ReadStv()

Returns

PinSite<double[]>

Raw captured bit values per pin/site. Values are 0 (below VOL), 1 (above VOH), or 255 (midband/undefined). Pins/sites with no captured data are omitted, including when HRAM captured no cycles at all (e.g. no trigger occurred).

Remarks

CapturedCycles is a scalar whose derivation across multiple sites with differing capture depths is undocumented, so the maximum captured-cycle count across active sites (via CapturedCyclesPerSite) is used to drive how many cycles are requested from ReadDataBits, avoiding truncation of sites captured with more cycles than others. Sites that captured fewer cycles than this maximum may be over-read as a result — a deliberate tradeoff, since truncating a site's real data is worse than reading a few extra (likely stale/undefined) cycles for it. When Size is positive it also bounds what's visible on readback, but IG-XL does not document what ReadDataBits does when the requested cycle count exceeds Size (unlike ReadCapturedCycleData, which is documented to clamp) — so the requested count is defensively clamped to Size here when Size is positive. Size <= 0 (hardware default depth, or max depth via -1) means no such limit applies.

Reads are issued via TheHdw.Digital.Pins(...) rather than through TheHdw.Digital.TimeDomains(_timeDomain), because Teradyne.Igxl.Interfaces.Public.DriverDigitalDomain does not expose a pin-scoped read API. In test programs that use multiple time domains over the same pins, this can resolve against the System time domain instead of _timeDomain.

Only DutCycleOffset 0 is read for every captured cycle. This is the only sub-cycle for 1X pins, but for 2X/4X pins the other 1-3 DUT sub-cycles per minor cycle are silently dropped. Handling the pin multiplier is a known limitation of this implementation.

Reset()

Clears the HRAM capture configuration. Call this after processing captured data to return the hardware to an idle state.

public void Reset()

Remarks

Size is intentionally not reset — it is inert once CaptureType is Teradyne.Igxl.Interfaces.Public.CaptType.None, and every new capture object sets its own Size before use.

HRAM's CaptureType and trigger arm state are shared per time domain, not scoped to this instance (see the constructor's remarks). Calling Reset() disarms the trigger for any HramCapture instance currently configured against the same time domain, not just this one.
