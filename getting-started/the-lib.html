Each box lists a few representative methods — the full, per-branch method tables follow below.

Validate

Runs once at flow load. Checks parameter ranges, parses enums, validates pin lists and patterns. If something is wrong, IG-XL shows a red validation error before any silicon is touched.

Key methods: InRange, GreaterOrEqual, LessOrEqual, Enum, IsTrue, Fail, Dc (instrument-specific parameter validation), Pins, Pattern.

Method Purpose
InRange Checks a value is within [from, to]
GreaterOrEqual / GreaterThan Lower-bound checks
LessOrEqual / LessThan Upper-bound checks
Enum Parses a string into a typed enum, lists valid options on failure
IsTrue Asserts a boolean condition with a custom message
Fail Unconditionally raises a validation error
Dc Validates DC parameter combinations per instrument type (PPMU, DCVI, DCVS)
GetObjectByClassName Resolves a class by name via reflection (for extensibility)

Setup

Prepares instruments for the measurement. Three sub-areas:

a. Setup.Dc

Connect/disconnect relays, force voltage/current, set meter mode and ranges. Automatically routes to the correct instrument (PPMU, DCVI, DCVS).

Method Purpose
Connect / Disconnect Relay control for DC pins
ConnectAllPins Connects all pins via levels & timing
Force Sets force voltage, current, or Hi-Z mode
ForceV / ForceI / ForceHiZ Granular force controls with ranges and clamps
Modify Updates any combination of DC parameters (gate, mode, voltage, current, ranges, meter, compliance, etc.) — instrument-aware routing to PPMU/DCVI/DCVS
SetForceAndMeter Combined force + meter configuration in one call
SetMeter Configures measurement mode (voltage/current), range, filter, averaging
CreateCaptureSignal Sets up a DCVS capture signal for waveform acquisition

b. Setup.Digital

Configure digital pin properties (levels, timing, alarms, frequency counter).

Method Purpose
Connect / Disconnect Digital relay control
FrequencyCounter Configures the frequency counter (event source, slope, window)
ModifyPins Alarm type/behavior, compare/drive enable, init/start state, calibration
ModifyPinsLevels Single-ended and differential voltage levels (VIH/VIL, VOH/VOL, VID, VICM, etc.), driver mode, per-site level overrides
ModifyPinsTiming Clock period/offset, edge set timing, auto-strobe, free-running clock, source-sync data delay, timing offsets

c. Setup.LevelsAndTiming

Apply the levels and timing sheet to hardware, optionally with power-up sequencing.

Method Purpose
Apply Applies levels & timing with options for connect-all-pins, unpowered mode, and level ramp sequences
ApplyWithPinStates Same as Apply but with explicit pin init states (Hi/Lo/HiZ) for controlled power-up sequencing

Execute

Runs the actual test stimulus:

a. Execute.Digital

Start/run/halt digital patterns, conditional stops with IExecutable callbacks, pattern-synchronized ramps.

Method Purpose
RunPattern Starts a pattern and waits for completion
StartPattern / WaitPatternDone Async pattern control
ForcePatternHalt Emergency pattern stop
RunPatternConditionalStop Runs a pattern with N flag-based breakpoints, executing an IExecutable at each stop
ContinueToConditionalStop Waits for a conditional stop, runs an action, then continues
RunPatternSyncRamp Starts a PPMU pattern-synchronized voltage ramp

b. Execute.ScanNetwork

Burst IJTAG scan patterns with CMEM configuration, run diagnosis on failed cores.

Method Purpose
RunPattern Configures CMEM and bursts the non-diagnosis scan pattern
RunDiagnosis Re-bursts failed cores with CMEM capture for diagnosis (sequential or concurrent)

c. Execute.Search

Post-process search sweep results (find closest-to-target or trip point from collected data).

Method Purpose
LinearFullProcess (target-based) Finds the input value whose output is closest to a numeric target (from a List<Site<T>> or Site<Samples<T>>)
LinearFullProcess (trip-based) Finds the first input value where the output meets a trip criterion (e.g., pass→fail transition)

d. Wait

A hardware settle wait, called directly on Execute rather than through a sub-block.

Method Purpose
Wait Hardware settle wait (static or parallel) with configurable timeout

Acquire

Captures measurement data from hardware. Contains four sub-blocks:

a. Acquire.Dc

Measure voltage/current (single, multi-sample, waveform), strobe for pattern-synchronized capture, read back previously captured data.

Method Purpose
Measure Single or multi-sample voltage/current measurement (PPMU/DCVI/DCVS)
MeasureSamples Returns Samples<double> arrays for waveform capture
Strobe / StrobeSamples Triggers a measurement without immediately reading (for pattern-synchronized measurements)
ReadMeasured / ReadMeasuredSamples Reads back previously strobed data
ReadCaptured / ReadCapturedSamples Reads DSP waveform data from a named capture signal

b. Acquire.Digital

Pattern pass/fail, HRAM data read (pin values or assembled words), frequency counter results.

Method Purpose
PatternResults Returns per-site pass/fail from the last pattern burst
Read Reads HRAM captured pin data as Samples<int> (H=1, L=0)
ReadWords Reads HRAM data as assembled words (configurable word size, bit order)
MeasureFrequency Reads frequency counter results

c. Acquire.Search

Iterative search algorithms (linear sweep, binary search) that call user-provided measurement lambdas.

Method Purpose
BinarySearch (double, target) Bisection search for a value closest to a numeric target
BinarySearch (double, trip) Bisection search for a pass/fail boundary
BinarySearch (int, target/trip) Integer versions of the above
LinearFullFromToCount / FromToInc / FromIncCount Full linear sweep (calls oneMeasurement at each step)
LinearStopFromToCount / FromIncCount (target) Linear sweep that stops early once all sites find target
LinearStopFromToCount / FromIncCount (trip) Linear sweep that stops early on trip criterion

d. Acquire.ScanNetwork

Extract per-core pass/fail from scan network results.

Method Purpose
PatternResults Extracts per-core/ICL-instance pass/fail results from a scan network pattern execution

Datalog

Pushes results to the IG-XL test flow for binning and data collection:

Method Purpose
TestFunctional Logs a per-site boolean pass/fail
TestParametric Logs int or double results against flow limits (Site or PinSite, single value or Samples). Auto-fills midway-pass values when running offline
TestScanNetwork Logs scan network results with per-core or per-ICL-instance fail flags and comments

When running offline, the Datalog block can auto-fill midway-pass values (controlled by a Behavior feature flag) so that offline flows don't fail on missing measurement data.
