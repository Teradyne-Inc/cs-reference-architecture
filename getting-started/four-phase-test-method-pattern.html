The Four Phase Test Method Pattern

Every test method in C#RA follows a four-phase structure inside a single method. This is the most important pattern to recognize:

Validate → Pre-body → Body → Post-Body

[TestMethod, Steppable, CustomValidation]
public void Baseline(PinList pinList, double current, double clamp, string setup = "") {

    // PHASE 1 — VALIDATE (runs once when the flow loads)
    if (TheExec.Flow.IsValidating) {
        TheLib.Validate.Pins(pinList, nameof(pinList), out _pins);
        TheLib.Validate.InRange(current, 0, 1.0, nameof(current));
    }

    // PHASE 2 — PRE-BODY (hardware preparation)
    if (ShouldRunPreBody) {
        TheLib.Setup.LevelsAndTiming.Apply(connectAllPins: true);
        Services.Setup.Apply(setup);
        TheLib.Setup.Dc.Connect(_pins);
    }

    // PHASE 3 — BODY (core measurement)
    if (ShouldRunBody) {
        TheLib.Setup.Dc.SetForceAndMeter(_pins, DcOutputMode.ForceCurrent, current, current, clamp, DcMeterMode.Voltage, 4.0);
        TheLib.Execute.Wait(0.001);
        _meas = TheLib.Acquire.Dc.Measure(_pins);
    }

    // PHASE 4 — POST-BODY (cleanup & datalog)
    if (ShouldRunPostBody) {
        TheLib.Setup.Dc.Disconnect(_pins);
        TheLib.Datalog.TestParametric(_meas, current, "A");
    }
}

Why Four Phases?

Phase When It Runs Purpose
Validate Once at flow load time Catch configuration errors before silicon is involved
PreBody Before each DUT test Set up instruments, apply voltage levels
Body The actual test Force, execute, measure
PostBody After each DUT test Disconnect hardware, log results to the datalog

The Prebody / Body / Postbody split is IG-XL's, not C#RA's — it comes from the [Steppable] attribute, which tells IG-XL to call the method three times during a debug run (once per phase) while executing it as a single step in a normal run. Teradyne documents the model in .NET Test Structure: Prebody, Body, Postbody, and the gating properties on TestCodeBase. What C#RA adds is the Validate phase in front of them, via [CustomValidation].

Conventions

  • Classes inherit from TestCodeBase and are decorated with [TestClass(Creation.TestInstance), Serializable].
  • Methods are decorated with [TestMethod, Steppable, CustomValidation].
  • using static Csra.Api; provides direct access to TheLib and Services. TheExec and TheHdw are not part of Csra.Api — they come from TestCodeBase, which the class already inherits.
  • Intermediate results (e.g., _pins, _meas, _patternInfo) are stored in private fields so they survive across the four phases.
  • The optional setup string parameter integrates with the SetupService for named hardware configuration sets.
Note

TestCodeBase, [TestClass], [TestMethod] and [Steppable] are IG-XL constructs, not C#RA ones — they behave exactly as they do in any IG-XL .NET test program, with or without C#RA. See Teradyne's .NET Attributes Supported in IG-XL for the full list. What C#RA contributes is [CustomValidation] and the TheLib / Services calls inside the phases.
