Download & Extract

To begin using the C#RA library, you'll first need to download and extract the package. This package includes the core source code, a demo project to help you get started quickly, and offline documentation for reference. Follow the steps below to set up your environment.

  • Visit the C#RA page on eKnowledge.
  • Download the latest C#RA package.
  • Unzip the contents to a location of your choice.

Content of the ZIP:

├── 📁Core
│   ├── 📁Csra                    # Source code of the library
│   └── 📁Tol                     # Thin Object Layer (per-instrument pin abstractions)
├── 📁ReferenceLibraries
│   ├── 📁CsraTestMethods         # Reference test methods built on C#RA
│   ├── 📁CsTestMethods           # Same tests written against the raw IG-XL API
│   ├── 📁UnitTests               # Example unit test project + reusable base class
│   └── 📁PortBridge              # PortBridge utilities and demo
├── 📁Demo                        # Sample IG-XL program demonstrating usage
├── csra_documentation.pdf        # Offline documentation
├── LICENSE.txt
└── README.md

This is the same content you can browse in the public repository at Teradyne-Inc/cs-reference-architecture. The hierarchy matches the development repository with the src/ prefix removed, so the relative ProjectReference paths inside the .csproj files keep resolving. Offline HTML documentation is delivered as a separate archive.

Note

The package does not ship a solution file, but it can build you one. Run Demo/generate-subset-solution.cmd and you get SOC124.sln with every shipped project already added and grouped:

  • Core — Csra, Tol, PortBridgeUtils
  • Examples — CsTestMethods, CsraTestMethods, UnitTestExample, Demo_PB

That is the quickest way to open the whole thing in Visual Studio and read or build it. Treat the script as a template: it is a short list of dotnet sln add lines, so edit it to assemble whatever subset your program actually needs — drop the examples you won't use, add your own projects, rename the solution. To use C#RA in a program of your own instead, add the projects to your existing solution — see Installation & Adding Reference.

Tip

You can create a Git repository for the Core/Csra folder and link it as a submodule in your main project repository.

Demo Project

For reference purpose a demo project is part of the release package. It shows how to use a TestMethod or a TestBlock from a 3rd party project.

└── 📁Demo
    ├── 📁ASCIIProgram             # IG-XL ASCII program files (flow, levels, timing, pins)
    │                                common, spCS, spCSRA, spPortBridge, spVBT
    ├── 📁Patterns                 # Digital test patterns
    ├── Demo.igxlProj              # IG-XL project
    ├── IG-ComponentManager.json   # Required IG-XL / Oasis / SSL / Visual Studio versions
    ├── SimulatedConfig.txt        # For simulating purposes
    ├── _LoadProgram.cmd           # Generates the program and loads IG-XL via IGLinkCL
    ├── _GenerateProgram.cmd       # Generates the program without loading IG-XL
    ├── generate-subset-solution.cmd # Template — edit it to assemble the subset solution you
    │                                  want; this specific one creates SOC124.sln
    └── README.md
Note

There is no .igxl workbook in the package. The program is generated from Demo.igxlProj and the ASCII files when you run _LoadProgram.cmd or _GenerateProgram.cmd — which is why the ASCII program, not a binary workbook, is the thing under version control.

The C# test methods themselves are not inside Demo — they live in ReferenceLibraries/CsraTestMethods (built on C#RA) and ReferenceLibraries/CsTestMethods (raw IG-XL API), and the demo program references them from there. The spCS and spCSRA ASCII sub-programs are what wire each of the two into the IG-XL flow.

To start IG-XL, just click on the _LoadProgram.cmd file. Both .cmd files detect PortBridge automatically through PBROOT and pass the matching IG-Link selector. Once IG-XL is started, open the Datalog window and hit Validate Job and Run at the IG-XL Main tab.

To debug the Test Program, click Visual Studio (Connected Mode) at the IG-XL Tools tab. Once Visual Studio is up, add breakpoints and hit Run again.
