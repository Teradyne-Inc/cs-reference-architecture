What C#RA Is

C#RA is a C# library for semiconductor test programs running on the Teradyne UltraFLEX+ platform (IG-XL). It replaces traditional VBA-based test development with a modern, strongly-typed, modular C# approach.

In plain terms: when a chip sits on the tester, a test program needs to configure instruments → run patterns → take measurements → log results. C#RA provides reusable building blocks for every one of those steps, so that test engineers can write test methods by composing blocks rather than re-implementing low-level hardware calls.

Note

UltraFLEX+ is the platform C#RA is developed and verified against. UltraFLEX is not validated and is not a supported platform.

The Core Value Proposition: Reusability

Without C#RA, engineers write C# test methods that call IG-XL public APIs directly (as shown in ReferenceLibraries/CsTestMethods/). This works, but the resulting code is project-specific — tightly coupled to one chip and customer, so every new program starts from scratch re-implementing the same measurement patterns.

C#RA solves this by providing a common reusable layer on top of the IG-XL APIs. The goal is to capture ~70% of test program logic as reusable library code, leaving only ~30% as customer-specific or chip-specific implementation. This dramatically reduces development time for new test programs and ensures consistency across projects.

┌──────────────────────────────────────────────────────────┐
│  ~70% Reusable (C#RA library + CsraTestMethods)          │
│  ┌─────────────────────────────────────────────────────┐ │
│  │  C#RA Blocks: Setup, Execute, Acquire, Datalog...   │ │
│  │  C#RA Test Methods: Continuity, Functional, etc.    │ │
│  └─────────────────────────────────────────────────────┘ │
│                                                          │
│  ~30% Customer-Specific                                  │
│  ┌─────────────────────────────────────────────────────┐ │
│  │  Custom pin mappings, special sequences,            │ │
│  │  chip-specific measurements, proprietary trim       │ │
│  └─────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘

When starting a new test program, engineers copy the C#RA library and CsraTestMethods, then only write the customer-specific ~30%. Extensibility — covered below, and in full in Extensibility — is how that customization is injected.

C#RA is also additive rather than exclusive: it does not close the door on the IG-XL public API. Anything C#RA does not yet cover can still be called directly as native C# from inside the same test method, alongside the TheLib calls. You are never blocked waiting for a library feature.

Extensibility

Every branch in TheLib and every service is accessed through an interface. You can swap any default implementation with your own:

// Replace the default Datalog block with a custom one
Api.TheLib.Configure(datalog: new MyCustomDatalog());

// Replace the Alert service
Api.Services.Configure(alert: new MyCustomAlert());

This is how customer-specific behavior is injected without modifying library code.
